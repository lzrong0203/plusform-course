### 第一輪：熊請家教解釋

熊：

```
我的帳本用 Python 算 0.1 + 0.2，印出來是 0.30000000000000004，不是 0.3。請用記帳的例子解釋為什麼，先不要給程式碼。
```

家教（白海豹）：

```
你已經說了你做了什麼、看到什麼結果，所以我直接進入解釋。

用記帳來想：三個人平分 1 元

假設你的帳本每筆金額只能寫到小數點後兩位。三個人平分 1 元，每人 1/3 元，帳上只能寫 0.33。三人加起來是 0.99，不是 1.00，差的 0.01 不是誰算錯，而是 1/3 在十進位裡是 0.3333...，永遠寫不完，只能在某個位置截斷。

電腦也有同樣的問題，只是換成二進位

電腦用二進位存數字，每個數字只有固定數量的位數可以用。有些數字在十進位很整齊，例如 0.1，換成二進位卻變成無限循環，就像 1/3 在十進位的狀況一樣。所以電腦存的 0.1 其實是「截斷後最接近 0.1 的值」，0.2 也是。兩個各自帶著一點點誤差的數字加起來，誤差就跑到最後幾位，變成 0.30000000000000004。

重點

這不是 Python 的 bug，幾乎所有語言都會這樣。
誤差極小，大約在第 16 位小數。
但帳本最在意「剛好等於」，所以這種微小差距會造成麻煩，例如比較兩個金額是否相等時。

回頭想一下：真實的帳本裡，金額最小單位通常是「分」或「元」，不會有「半分」。如果你想避開這種誤差，你覺得可以怎麼換個方式表示金額？另外，你有試過自己處理這個問題嗎？
```

## 2. Python 官方文件的原文

- 浮點數（官方教學第 15 章〈Floating-Point Arithmetic: Issues and Limitations〉，https://docs.python.org/3.13/tutorial/floatingpoint.html ）：
  - 「Unfortunately, most decimal fractions cannot be represented exactly as binary fractions.」（大部分的小數，沒辦法用二進位剛好存下來。）
  - 「Note that this is in the very nature of binary floating point: this is not a bug in Python, and it is not a bug in your code either.」（這是二進位浮點數本來的性質：不是 Python 的 bug，也不是你程式的錯。）
  - 同一章也說，先用 round() 把每個數字四捨五入再比較，一樣沒辦法讓它們剛好相等；要精確的小數運算可以用 decimal 模組（「suitable for accounting applications」）。這門課的帳本只記到元，用整數就夠了。
- None（https://docs.python.org/3.13/library/constants.html ）：「An object frequently used to represent the absence of a value」（常用來表示「沒有值」）。
- 數字型別（https://docs.python.org/3.13/library/stdtypes.html ）：「Integers have unlimited precision.」整數存得剛好，多大都可以。
- type()（https://docs.python.org/3.13/library/functions.html#type ）：「With one argument, return the type of an object.」
- TypeError（https://docs.python.org/3.13/library/exceptions.html ）：「Raised when an operation or function is applied to an object of inappropriate type.」（型別不對，不能這樣用。）

影片裡的輸出（type() 印出的 `<class 'int'>`、0.1 + 0.2 印出的 0.30000000000000004、`"100" + 20` 的 TypeError 原文）都是用 Python 3.13 實際跑出來的。

## 3. 幾個容易誤會的細節

- **`<class 'int'>` 是什麼？** type() 告訴你的是資料的「類別」，影片只要你看引號裡面那個字。類別是 1-24 才教的東西。
- **bool 其實是 int 的一種。** 官方文件寫「bool is a subclass of int」，所以 `True + 1` 會得到 2。但 `type(True)` 印出來是 `<class 'bool'>`，不是 int；官方也說不要依賴 True 當 1 用，要數字就用 int() 換。這課的作業照 type() 印出來的寫：True、False 是 bool。
- **None、0、空字串不一樣。** 0 元是真的花了零元；`""` 是一段沒有字的文字；None 是「這裡還沒有東西」。帳本裡還沒填的欄位用 None。
- **120 和 120.0 用 == 比，Python 說它們相等**（數值一樣），可是型別不一樣。第③圈的 check 會連型別一起比，所以案例表右邊寫 120.0 會被當成不對：需求要的是整數元。
- **美金這種有小數的錢怎麼辦？** 換成最小的單位存整數，例如 1.25 美元存成 125 美分。要算到小數也可以用官方的 decimal 模組，以後用得到再教。
- **int() 會自己忽略前後的空白。** 所以轉換機收到 `" 35 "` 也轉得出 35。int()（把文字換成整數）在 1-6 會細講。

## 4. 第③圈：案例表怎麼寫

- 一行一組：`"120" -> 120`。左邊是丟進轉換機的文字（前後加半形引號），中間是箭頭 `->`（減號加大於），右邊是應該變成的整數（不加引號、不加小數點、不寫「元」）。
- `#` 開頭的是說明，check 不看。有「？」的行算還沒寫完。
- 5 組裡要有 1 組是「連正確版都轉不了」的金額，在那一行最後加 `# 已知會當掉`，右邊可以不寫。1-22 學錯誤處理時再回來修它。
- check 一開始只給你看第一個沒過的；想一次看全部，加 `--all`。
