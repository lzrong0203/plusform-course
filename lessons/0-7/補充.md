# 0-7 補充：存檔點，讓 AI 改壞了也不怕

影片說明欄放不下的參考資料。作業的完整步驟在同一個資料夾的 [README.md](README.md)。

## 指令與按鈕小抄（照影片的順序）

1. `git config --global user.name "你的名字"`：告訴 git 你的名字。`--global` 是這台電腦上的每個資料夾都用這個設定，只要做一次。名字中間有空格要用引號包起來。
2. `git config --global user.email 你的信箱`：告訴 git 你的信箱。成功時什麼都不印。
3. VS Code 左邊像樹枝分岔的圖示＝原始碼控制（Source Control）→ **Initialize Repository**：建立存放庫（等於在終端機打 `git init`），帳本裡會多一個藏起來的 `.git` 資料夾。
4. 上面的框寫一句說明 → **Commit** → 跳出 `There are no staged changes to commit. Would you like to stage all your changes and commit them directly?` 按 **Yes**：按下存檔點。
5. 改檔案、按 ⌘S（Windows：Ctrl+S）：只是把檔案存起來，原始碼控制的清單會出現那個檔案（M＝改過、U＝git 還沒記過）。
6. 按清單裡的檔案：打開差異畫面，左邊是存檔點的樣子、右邊是現在的樣子；紅色是被改掉的、綠色是改成的。
7. 滑到那一列 → 往回轉的箭頭（**Discard Changes**）→ **Discard File**：丟掉這次的改動，回到存檔點。
8. 改好一段 → 再寫一句說明、按 **Commit**：再按一個存檔點。Graph 會多一個圓點。
9. `git clone https://github.com/lzrong0203/plusform-course.git`：把課程資料夾連同所有存檔點複製下來（公開的，不用登入）。
10. `git pull`：在課程資料夾裡打，把網路上新的存檔點拿下來；已經是最新版會說 `Already up to date.`

這課先不要按的：**Publish to GitHub**、**Publish Branch**（放上網路用的，2-1 開 GitHub 帳號以後再說）。

## 信箱：先填不介意公開的，2-1 換成 noreply

- 你設的名字和信箱，會寫進以後的每一個存檔點。存檔點放上 GitHub 以後，別人看得到信箱；改了信箱以後，以前的存檔點還是舊的信箱（GitHub Docs〈Setting your commit email address〉：Any commits you made prior to changing your commit email address are still associated with your previous email address.）。
- 2-1 開好 GitHub 帳號以後，在 GitHub 的 Settings → Emails 勾 **Keep my email addresses private**，會拿到一個 `ID+帳號@users.noreply.github.com` 的信箱，再打一次 `git config --global user.email 那個信箱` 換掉（GitHub Docs〈Email addresses reference〉）。
- 名字和信箱只是寫在存檔點上的「作者」，不是登入用的帳號密碼（VS Code Docs：These values identify the author in Git history, not your sign-in credentials.）。

## 沒設名字和信箱會怎樣？

- 在這門課錄影用的 Mac 和 Windows 虛擬機上，按存檔點會失敗：VS Code 跳出 `Make sure you configure your "user.name" and "user.email" in git.`，終端機是 `Author identity unknown … Please tell me who you are.`（2026-11-14 實測）。
- 有些電腦不會失敗：git 會自己拿「電腦的帳號名稱＋電腦名稱」來湊一個信箱（git 官方文件 git-commit 的 COMMIT INFORMATION 一節）。這樣反而更糟：你電腦的帳號名稱會寫進存檔點裡。所以一開始就自己設好。

## 你的畫面跟影片不一樣？

- 提示字元前面是你自己的帳號和電腦名稱（影片是示範用的 `bear@MacBook-Air`），路徑也會是 `/Users/你的帳號`。
- VS Code 的版本可能比影片新（影片是 1.146.0），按鈕的位置大致一樣。VS Code 改成中文介面的話，按鈕會是中文；這門課的影片都用英文介面，照按鈕的位置找就好。
- Commit 的框裡如果有一個閃亮的小圖示（用 AI 幫你寫說明），代表內建 AI 功能沒關；0-6 教過怎麼關。第①圈和檢核時請關著，說明自己寫。
- 按 Commit 時沒有跳出「There are no staged changes…」的問題：可能你以前按過 **Always**（VS Code 的 Smart Commit：Commit all changes when there are no staged changes），它就直接存了，沒關係。
- 檔案清單比影片多或少：影片的帳本有 0-4、0-5 的作業檔，一共 14 個；`.venv` 和 `.check` 不會出現（uv 和 check.py 在裡面放了 `.gitignore`）。
- 右下角的分支名稱寫 `main`：VS Code 建的存放庫預設叫 main。用終端機打 `git init` 的話，Windows 的 Git for Windows 預設可能叫 `master`，都沒關係。
- 開了自動存檔（0-6 教過）：改完不用按 ⌘S，清單會自己出現那個檔案。

## Windows

- git 跟著 Git for Windows 裝好了（0-W 第 1 章），兩行 `git config` 在 Git Bash 照打。
- ⌘ 一律換成 Ctrl：存檔 Ctrl+S、Commit 的快捷鍵 Ctrl+Enter。
- VS Code 原始碼控制的畫面、按鈕都一樣（2026-11-14 在 Windows 11 虛擬機實測：Git for Windows 2.56.1、VS Code 1.146.0）。跳出來的問題是 Windows 的系統視窗，按鈕一樣是 Yes、Always、Never、Cancel。
- **換行警告**：Windows 和 Mac 存檔時的「換行」寫法不一樣，Git for Windows 安裝時預設會幫你轉換（Checkout Windows-style, commit Unix-style line endings，`core.autocrlf` 設成 true）。在 VS Code 按存檔點不會跳出任何提醒；只有打開 Output 的 Git 紀錄，或在 Git Bash 打 `git add`，才會看到 `warning: in the working copy of 'main.py', LF will be replaced by CRLF the next time Git touches it`。這是正常的，不用處理。

## 名詞小抄

| 名詞 | 意思 |
|---|---|
| 存檔點（commit） | 把整個資料夾在某一刻的樣子記下來，之後改壞了回得去 |
| git | 幫資料夾記存檔點的工具 |
| 存放庫（repository） | git 放存檔點的地方，就是帳本裡藏起來的 `.git` 資料夾 |
| 原始碼控制（Source Control） | VS Code 裡按存檔點、看差異、退回的那個面板 |
| 差異（diff） | 存檔點跟現在比，哪裡不一樣；紅色是被改掉的、綠色是改成的 |
| Discard Changes | 丟掉還沒存進存檔點的改動，回到存檔點；丟了就找不回來 |
| git clone | 把網路上的存放庫連同所有存檔點，整個複製一份到你的電腦 |
| git pull | 把網路上新的存檔點拿下來，更新你的那一份 |
| agent | 會自己在電腦上動手的 AI |
