# 1-10　while 迴圈

這課大約 45 分鐘。三圈比例 70／20／10。Windows 同學：指令在 Git Bash 照打，⌘ 換成 Ctrl（安裝見 0-W）；程式停不下來的時候，一樣按 Ctrl+C。
要會的：`input()` 和 `int()`（1-6）、比較 `<`、`<=`、`!=`（1-8）、`if`（1-9）。

## 1. 題目

**第①圈：自己寫（關掉 AI）。**

A. 迴圈跑幾次（`loops.txt`）：先不要跑，用眼睛追 4 段 while，寫出跑幾次、會不會停。

B. 記帳，一直記到打 q 為止（`record.py`）：

1. 一直問金額（提示字寫「金額，打 q 結束：」），每打一筆就加進合計
2. 打 q 就停下來，最後印出「一共 ○○ 元」
3. 不小心多按一下 Enter（什麼都沒打）的時候，這一次跳過、再問一次（用 `continue`）

**第②圈：用「帶我寫」跟家教寫（`max10.py`）。** 把 `record.py` 那種記帳程式改成**最多記 10 筆**：記滿 10 筆就自己停，打 q 可以提早結束，空白的一行不算一筆，最後印出「一共 ○ 筆，合計 ○○ 元」。在家教專案裡打「帶我寫：……」，**每一步你先說要做什麼，家教才給那一步的寫法**（0-8 教過）。`lead_quiz.txt` 有三個問題；你說了什麼、家教給了什麼，記在 `lead.md`（自評，不擋過關）。

**第③圈：替 AI 寫的記帳程式準備輸入和預期輸出（`inputs.txt`、`expected.txt`）。** 需求卡：

| 欄 | 內容 |
|---|---|
| 目標 | 一直記到打 q 為止，最後印出一共幾筆、合計多少 |
| 背景 | 有時候會不小心多按一下 Enter（什麼都沒打的一行） |
| 限制 | q 不算一筆；空白的一行跳過，也不算一筆 |
| 怎樣算做完 | 你的 inputs.txt 和預期輸出，正確版跑起來一模一樣；三個壞版本，各被你抓到 |

課程準備了一個正確版（`reference/tally.py`）和三個壞版本（`mutants/`），其中一個**把 q 也算成一筆**。你不用看它的程式：`inputs.txt` 一行寫一個要打的字（最後一行一定是 `q`），`expected.txt` 寫它應該印出來的那一行。`uv run check.py 1-10` 會把你的 `inputs.txt` 餵給四個版本，把印出來的跟你的預期輸出一行一行比。

## 2. 提示

- `while 條件:` 的意思是：只要條件成立，就一直做下面縮排的那幾行。每一圈開始前都先看一次條件，不成立就跳到迴圈下面那一行。第一次看條件就不成立，迴圈一次都不跑。
- 算跑幾次：把每一圈開始時的變數值寫下來（1、2、3……），看它變成多少的時候條件不成立。
- 靠條件停下來的 while，**迴圈裡要有一行，讓條件有機會不成立**（例如再問一次金額、`n = n + 1`），或是用下面的 `break` 跳出去。兩個都沒有，條件永遠成立，程式停不下來，這叫**無窮迴圈**。自己試跑遇到了，在終端機按 **Control C**（Windows 是 Ctrl+C），錯誤訊息最後一行是 `KeyboardInterrupt`，意思是你按了中斷。
- `while True:` 條件永遠成立，什麼時候停交給 `break`：`break` 讓**整個迴圈結束**，跳到迴圈下面那一行。
- `continue` 只**跳過這一圈剩下的**，回到 `while` 重新看條件。用在「先問一次、迴圈最後再問一次」的寫法時要小心：continue 會把最後那一行「再問一次」也跳過，又變成無窮迴圈（第③圈的壞版本 2 就是這樣）。
- 第②圈：`count = count + 1` 要放在 `break`、`continue` 的**下面**，真的記了一筆才加；放在 `input` 的下一行，打 q 也會被算成一筆。
- 第③圈：寫 `inputs.txt` 的時候，回頭看需求卡的「背景」和「限制」：需求說會遇到的情況，就放進你的輸入裡試。

## 3. 開始前要打的指令

```bash
cd ~/code/plusform-course
git pull
uv run check.py start 1-10
```

它會把起點檔複製到你的帳本 `lessons/1-10/`：`loops.txt`、`record.py`、`max10.py`、`lead_quiz.txt`、`lead.md`、`inputs.txt`、`expected.txt`。

用 VS Code 打開帳本，寫完存檔，在 VS Code 下面的終端機（帳本資料夾）自己跑跑看：

```bash
uv run lessons/1-10/record.py
uv run lessons/1-10/max10.py
cd ~/code/plusform-course
uv run check.py 1-10
```

檢查的時候要**回到課程資料夾**（上面第三行）再打 `uv run check.py 1-10`。

（也可以不切資料夾，直接打完整路徑：`uv run ~/code/plusform-course/check.py 1-10`。）

## 5. 怎麼測

`uv run check.py 1-10` 會先問你：「你覺得會過幾題？」先猜一個數字再按 Enter，它才開始檢查。一共 18 題：

- 第一圈：`loops.txt` 4 題、`record.py` 3 題（check 自己餵三組：120、85、q；一開始就打 q；中間多一行空白）
- 第二圈：`max10.py` 3 題（連打 12 筆都沒打 q；120、85、q；中間多一行空白）、`lead_quiz.txt` 3 題
- 第三圈：至少寫 1 行預期輸出、在正確版上一模一樣、抓到 3 個壞版本

**check 有逾時**：你的程式（和課程的每個版本）每跑一次最多等 5 秒，還沒結束就停下來，說「可能有無窮迴圈」，不會跟著卡住。

沒過的，它只先告訴你第一個沒過的，修好再跑一次（想一次看全部，最後加 `--all`）。不到 10 分鐘就全對，它會印出提醒：只是提醒，不扣分。`lead.md` 是自評，check 不檢查。

### 常見錯誤

| 你看到 | 意思 | 怎麼辦 |
|---|---|---|
| 自己試跑一直印、停不下來 | 無窮迴圈：條件永遠成立 | 在終端機按 Control C（Windows 是 Ctrl+C）；再找迴圈裡哪一行會讓條件變成不成立 |
| `KeyboardInterrupt` | 你按了 Control C，程式被中斷了 | 這是你自己停的，不是程式寫錯；回頭修迴圈 |
| `跑了 5 秒還沒結束，被停下來了` | check 跑你的程式，5 秒還沒結束 | 同上：迴圈裡要再問一次金額，或打 q 的時候 break |
| `ValueError: invalid literal for int() with base 10: ''` | 空白的一行交給了 int() | 先 `if text == "": continue` 跳過 |
| `inputs.txt 的 N 行都讀完了，正確版還在問` | 你的 inputs.txt 最後一行不是 q | 最後一行寫 `q` |
| `error: Failed to spawn: check.py` | 你不在課程資料夾裡 | 先打 `cd ~/code/plusform-course` |
