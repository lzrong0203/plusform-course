# 2-1 補充：開 GitHub 帳號，第一次讓 AI 碰你的專案

影片放不下、說明欄也放不下的內容放這裡：官方步驟的原文、家教的完整對話、對答題的說明。官方文件是 2026-11-19 擷取的（GitHub Docs、VS Code 官方文件），畫面和字樣以後可能會改，照你看到的最新版做。

## 1. 這一課的三條規矩

從第 2 級起，VS Code 裡的 Copilot 可以用 agent 模式改你的檔案、跑指令。規矩只有三條：

1. **交給它之前先存檔**（按一個存檔點）。改壞了，回到交辦前的樣子。
2. **它要執行的指令，看懂才按同意。** 看不懂、或跟交辦的事無關（裝套件、刪檔、丟掉改動），就按拒絕，先問它為什麼。
3. **改完看 diff、跑檢查，收不收由你決定。** 收了，再按一個存檔點。

「逐一按同意」是新手階段。VS Code 官方文件也提醒：Approval fatigue. Repeatedly approving commands can cause you to pay less attention to what you're approving（同意按多了，會越來越不仔細看）。第 5 級會改成事先寫好的規則（允許清單、沙盒）。

## 2. 開 GitHub 帳號、兩步驟驗證（GitHub Docs）

- 〈Creating an account on GitHub〉：To get started with GitHub, you need to have a personal account and a verified email address.（要有一個帳號，和一個驗證過的信箱。）到 https://github.com/signup 照畫面填；During sign up, you'll be asked to verify your email address. 帳號名稱會公開。
- 同一頁的 Next steps：We strongly recommend that you configure 2FA for your account. 2FA is an extra layer of security that can help keep your account secure.
- 〈Configuring two-factor authentication〉的步驟（用驗證 App，官方：TOTP applications are more reliable than SMS）：
  1. 在手機或電腦裝一個驗證 App（TOTP app）。
  2. GitHub 任何一頁右上角的頭像 → **Settings**。
  3. 左邊 Access 區 → **Password and authentication**。
  4. Two-factor authentication 那一區 → **Enable two-factor authentication**。
  5. 用驗證 App 掃 QR code，把 App 顯示的六位數填回 GitHub（掃不了就按 setup key 手動輸入）。
  6. **Save your recovery codes → Download**，存在安全的地方：your recovery codes can help you get back into your account if you lose access（手機掉了，靠它登回去）。
  7. 按 **I have saved my recovery codes**，兩步驟驗證就開好了。
- 官方也寫：開好以後有 28 天的確認期（28-day check up period），這段時間內用兩步驟驗證登入一次就好。

## 3. git 的信箱換成 noreply 信箱

0-7 設的 git 信箱會寫進每一個存檔點。之後把帳本放上 GitHub（3-3），看得到存檔點的人就看得到它。

- 〈Email addresses reference〉：If you created your account after July 18, 2017, your noreply email address is an ID number and your username in the form of `ID+USERNAME@users.noreply.github.com`.
- 在 GitHub：Settings → 左邊 **Emails** → 確認 **Keep my email addresses private** 是 **On**（2026-11 的畫面是一個開關），下面會寫出你的 noreply 信箱。照抄那一個，不要自己拼。
- 在終端機（〈Setting your commit email address〉）：

```bash
git config --global user.email 你的noreply信箱
git config --global user.email
```

- 官方：Any commits you made prior to changing your commit email address are still associated with your previous email address.（換了以後，以前的存檔點還是記著舊的信箱。）

在練習用的資料夾實際跑過（示範的信箱是格式範例，不是真的帳號）：

```
$ git --version
git version 2.50.1 (Apple Git-155)
（結束碼 0）
$ git config --global user.email
bear@example.com
（結束碼 0）
$ git config --global user.email 12345678+plusform-bear@users.noreply.github.com
（結束碼 0）
$ git config --global user.email
12345678+plusform-bear@users.noreply.github.com
（結束碼 0）
$ git config user.email
12345678+plusform-bear@users.noreply.github.com
（結束碼 0）
$ git log --format=%an <%ae> %s
PyPy Bear <12345678+plusform-bear@users.noreply.github.com> 第二個存檔點
PyPy Bear <bear@example.com> 第一個存檔點
（結束碼 0）
--- git checkout -- .（改過的檔回到存檔點、從沒存過的新檔不動）
$ git status --short
 M main.py
?? new.txt
（結束碼 0）
$ git checkout -- .
（結束碼 0）
$ git status --short
?? new.txt
（結束碼 0）
```

最後那一段順便看了 `git checkout -- .`：改過、還沒存進存檔點的檔，全部改回上一個存檔點的樣子；從來沒存過的新檔不受影響（commands.txt 第 3 題）。

1. 0-6 關掉的內建 AI 要打開：⌘ 逗號打開設定，搜尋 `disable ai`，把 **Chat: Disable AI Features** 的勾拿掉（官方：You can disable the built-in AI features in VS Code with the chat.disableAIFeatures setting）。

3. 官方：Without a plan, signing in enrolls an eligible account in Copilot Free.（還沒有 Copilot 方案的帳號，登入時會開成 Copilot Free。）
4. 登入好以後，狀態列的 Copilot 圖示按下去，最上面寫 **Copilot Free**（示範帳號 2026-11-19：Credits 0% used、Resets Dec 1）。
5. 打開右邊的 Chat（⌃⌘I），它就是 agent。輸入框下面兩個選單（VS Code 1.146 的字樣）：

   - 權限 **Default permissions**：Asks when approval settings don't apply（照設定，設定沒說可以的就先問你）。另外兩個 **Allow all**（Runs tool calls without asking）、**Autopilot (Preview)**（Works autonomously within permissions）不會一個一個問你，這一級先不要選。
   官方文件把預設叫 Manual permissions (default)：Actions that are not auto-approved require your confirmation.

**Copilot Free 方案頁（GitHub Docs〈Plans for GitHub Copilot〉）原文**：Copilot Free 那一列 Pricing「Free」、GitHub AI Credits「An allowance of GitHub AI Credits」、Agents「Limited」；Agents 表 Agent mode 那一列 Copilot Free 打勾（Included）。頁面寫 Copilot Free and Copilot Student both have an allowance of AI credits，沒有寫數字。用了多少，看 VS Code 狀態列的 Copilot 面板（官方：the percentage of your monthly allowance that you used）。

## 5. 它要執行指令時，按之前看什麼（VS Code 官方文件〈Manage approvals and permissions〉）

- Always review tool parameters carefully before approving, especially for tools that modify files, run commands, or access external services.
- By default, common read-only commands run automatically, while risky commands such as `rm` and `del` require approval.（常見的唯讀指令可能直接跑；`rm` 這種一定先問你。）
- Terminal auto-approval is a best-effort convenience, not a security boundary.（自動同意只是方便，不是保護。）

按之前問自己三件事：它要做什麼（讀、跑、改、刪，還是裝東西）？跟交辦的事有沒有關？看不懂，就按拒絕，先問它為什麼。

## 6. Keep、Undo、Restore Checkpoint 收不回什麼（VS Code 官方文件〈Review and revert agent changes〉、quickstart）

- Keep retains the changes and clears their pending-review state. Undo reverts them without rewinding the agent conversation.
- Pending edits are already saved to disk, so running your application or tests uses the changed files. You don't need Git to review them, and **Keep doesn't stage or commit them**.（Keep 不會幫你按存檔點。）
- **The working set only tracks changes from supported agent edit tools. Changes made through terminal commands, scripts, or other untracked tools don't appear.**（Undo 管的那份清單，只記 agent 用編輯工具改的檔；終端機指令改的不在裡面。）
- Restore Checkpoint … restores affected workspace files and chat history. **It doesn't reverse terminal commands**, network requests, deployments, or changes to external services.

所以第②圈家教說 `pyproject.toml`、`uv.lock`「Undo 或許還能動到」，官方文件的答案是：那是 `uv add` 在終端機改的，不在 Undo 的清單裡。AI 說「或許」的地方，就去官方文件查。收不回來的事，靠交辦前的存檔點。

## 10. 對答題的說明（作業做完再看）

**第 1 題（uv run）答案 A。** uv run 檔名＝用帳本自己的 Python 跑那支程式（0-5 起每一課都在打）。帳本沒有要另外裝的套件，它就只是跑一次報表給你看、不改檔，看懂了就可以按同意（專案設定裡寫了套件的話，uv run 跑之前會先把它們裝好，2-2 會看到）。

**第 2 題（pip install）答案 B。** pip install＝從網路下載、安裝一個套件。交辦時說好不裝套件；這門課裝套件一律用 uv add（2-2 教），寫進 pyproject.toml。C 也不對：Undo 只還原它改的檔案，終端機裡跑過的指令收不回來（VS Code 官方文件：Restore Checkpoint doesn't reverse terminal commands）。

**第 3 題（git checkout -- .）答案 C。** git checkout -- . 會把這個資料夾裡改過、還沒存進存檔點的檔案，全部改回上一個存檔點的樣子（跟 0-7 的 Discard Changes 一樣，只是一次全部；從來沒存進存檔點的新檔案不受影響）。你改到一半的東西會不見，而且交辦時沒請它這樣做。看不懂或覺得不對，就先按拒絕，問它為什麼要這樣做。

**第 4 題（rm）答案 A。** rm＝刪除檔案（0-4），在終端機刪掉的檔案不會進垃圾桶。expected.txt 是你寫的驗收標準，AI 沒有理由刪它：拒絕。VS Code 官方文件也寫，rm 這種有風險的指令預設要你同意才會跑。
