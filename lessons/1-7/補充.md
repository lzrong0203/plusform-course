## 1. 錯誤訊息怎麼讀（影片的整理）

從最下面往上看：

1. **最後一行**：冒號前面是錯誤的種類（`NameError`、`TypeError`……），後面是 Python 說的原因。
2. **往上一行**：`^` 和 `~` 指出這一行程式裡是哪一段出事（有些錯誤沒有這一行）。
3. **再往上**：出事的那一行程式。
4. **再往上**：`File "…/p4.py", line 6, in <module>`：哪個檔案、第幾行。`<module>` 是「程式的最外層」，這一級的程式都會是它。
5. **最上面**：`Traceback (most recent call last):`，「最近發生的放在最後面」，所以從最下面看。之後學到自己寫函式（1-18），中間會疊好幾段 File，一樣從最下面往上看。

`SyntaxError`、`IndentationError` 是 Python 看不懂寫法：整支程式一行都不跑，錯誤訊息也沒有 `Traceback` 那一行（1-1 看過）。
`NameError`、`TypeError`、`ValueError`、`ZeroDivisionError` 是跑到那一行才發現：前面的行已經跑了，印出來的字會在錯誤訊息上面。

錯誤出現的地方，不一定是要改的地方。官方教學 8.1 也這樣寫（原文在第 4 節）。錯誤訊息引號裡的值不對（像 p8 的 `'午餐'`），就往上找它是哪一行設的。
`Did you mean` 是 Python 照名字長得像不像猜的：p4 猜對了（totl → total），第③圈的 trip.py 猜錯了（days → day1，其實要的是天數 day_count）。

## 3. 第②圈：同一個錯，兩種求救（逐字紀錄）

示範帳號、0-8 建好的家教專案「PyPy 熊的程式家教」，2026-11-15 在 Claude 網頁版（模型 Sonnet 5.5）實際錄的。兩個對話是同一個專案裡各開一個新對話（帳號的記憶關著，兩邊互相看不到）。AI 的回答沒有改過；同樣的問題，每次問的回答可能不同。

總金額：1450
幾個人：4

### 第一種：只說「不能跑」

**熊（使用者）：**

```
我的分帳程式不能跑，怎麼辦？
```

**家教（Claude）：**

好的，我們來一起把它修好！先不急著看答案，我需要先了解你的情況：

你的程式碼長什麼樣子？ 可以把分帳程式貼上來嗎？（如果很長，貼出出問題的那一段也可以）

你試著執行時，看到了什麼？ 如果有紅色的錯誤訊息，請完整貼上，特別是最後一行（例如 SyntaxError、NameError、TypeError 之類的）。

你已經試過什麼方法？ 例如有沒有改過哪裡、重新執行過幾次，結果有變化嗎？

另外也告訴我一下，「不能跑」是指：

一執行就跳出錯誤訊息，

還是可以執行，但算出來的結果不對，

或是執行後完全沒有任何反應？

這三種情況要查的方向不一樣，你的回答會幫我們很快縮小範圍。

### 第二種：四樣一次給（出事的程式、完整的錯誤訊息、我猜的原因、我試過什麼）

**熊（使用者）：**

```
我的分帳程式跑到最後一行就當掉了。我打的總金額是 1450，人數是 4。
程式：
total = int(input("總金額："))
people = int(input("幾個人："))
print("每人 " + total // people + " 元")
完整的錯誤訊息：
Traceback (most recent call last):
  File "/Users/bear/code/ledger/lessons/1-7/split.py", line 3, in <module>
    print("每人 " + total // people + " 元")
          ~~~~~~~~^~~~~~~~~~~~~~~~~
TypeError: can only concatenate str (not "int") to str
我猜的原因：// 算出來的不是整數？
我試過：把 // 改成 /，還是 TypeError，只是最後一行的 int 變成 float。
```

**家教（Claude）：**

你已經先試了改 // 成 /，還能觀察到「int 變成 float」，這個觀察很好。

先看你的猜測：// 算出來的是整數嗎？你可以自己驗證：把 total // people 單獨放進 print(type(total // people))，看它印出什麼。你應該會發現，// 的結果確實是整數，所以問題不在它。

那再回頭看錯誤訊息最後一行：can only concatenate str (not "int") to str。請你用自己的話翻譯一下：

「concatenate」是在做什麼動作？

哪個東西是 str、哪個是 int？

另外，你把 // 改成 / 之後，錯誤訊息裡的 int 變成了 float，卻還是 TypeError。這暗示了什麼？問題是出在「算出來的數字是整數還是小數」，還是出在別的地方？

先回答我這兩個小問題，再想想 + 左右兩邊的東西是不是同一種型別。

影片裡熊照家教說的驗證：`print(type(1450 // 4))` 印出 `<class 'int'>`，`print(type(1450 / 4))` 印出 `<class 'float'>`：`//` 的結果確實是整數，熊猜錯了。真正的原因是 `+` 的左邊是字串、右邊是整數；熊改成 f-string `print(f"每人 {total // people} 元")`，印出「每人 362 元」。

自己問的時候，四樣照這個順序寫就好；不要貼密碼、個資、真實帳單（0-8）。家教說的話，要能對到錯誤訊息的哪一段，自己跑過再相信。

## 4. Python 官方文件的原文

**教學第 8 章〈錯誤和例外〉8.1、8.2**（https://docs.python.org/zh-tw/3.13/tutorial/errors.html ，繁體中文版；英文版 https://docs.python.org/3.13/tutorial/errors.html ）：

```
8.1. 語法錯誤 (Syntax Error)¶
語法錯誤又稱剖析錯誤 (parsing error)，它或許是學習 Python 的過程最常聽見的抱怨：
>>> while True print('Hello world')
  File "<stdin>", line 1
    while True print('Hello world')
               ^^^^^
SyntaxError: invalid syntax
剖析器 (parser) 會重複犯錯的那一行，並用一個小箭頭指向該行檢測到錯誤的地方，但請注意這並非都會是應該去修改的地方。此例中，錯誤是在 print() 函式中被檢測到，因為在它前面少了一個冒號 (':')。
檔案名稱（此例中為 <stdin>）和列號會被印出來，所以如果訊息是來自一個檔案時，就可以知道去哪裡找問題。
8.2. 例外 (Exception)¶
即使一段陳述式或運算式使用了正確的語法，嘗試執行時仍可能導致錯誤。執行時檢測到的錯誤稱為例外，例外不一定都很嚴重：你很快就能學會在 Python 程式中如何處理它們。不過大多數的例外不會被程式處理，並且會顯示如下的錯誤訊息：
>>> 10 * (1/0)
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
    10 * (1/0)
          ~^~
ZeroDivisionError: division by zero
>>> 4 + spam*3
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
    4 + spam*3
        ^^^^
NameError: name 'spam' is not defined
>>> '2' + 2
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
    '2' + 2
    ~~~~^~~
TypeError: can only concatenate str (not "int") to str
錯誤訊息的最後一行指示發生了什麼事。例外有不同的類型，而類型名稱會作為訊息的一部份被印出。範例中的例外類型為：ZeroDivisionError、NameError 和 TypeError。作為例外類型被印出的字串，就是發生的內建例外 (built-in exception) 的名稱。所有的內建例外都是如此運作，但對於使用者自定的例外則不一定需要遵守（雖然這是一個有用的慣例）。標準例外名稱是內建的識別字 (identifier)，不是保留關鍵字 (reserved keyword)。
此行其餘部分，根據例外的類型及導致例外的原因，說明例外的細節。
錯誤訊息的開頭，用堆疊回溯 (stack traceback) 的形式顯示發生例外的語境。一般來說，它含有一個列出源程式碼行 (source line) 的堆疊回溯；但它不會顯示從標準輸入中讀取的程式碼。
Built-in Exceptions章節列出內建的例外及它們的意義。
```

重點的英文原句：「Note that this is not always the place that needs to be fixed.」（小箭頭指的不一定是要修的地方）、「The last line of the error message indicates what happened.」（錯誤訊息的最後一行說明發生了什麼）。

**內建例外**（https://docs.python.org/3.13/library/exceptions.html ），這一課的六種：

- `SyntaxError`：Raised when the parser encounters a syntax error.
- `IndentationError`：Base class for syntax errors related to incorrect indentation. This is a subclass of SyntaxError.
- `NameError`：Raised when a local or global name is not found.
- `TypeError`：Raised when an operation or function is applied to an object of inappropriate type.
- `ValueError`：Raised when an operation or function receives an argument that has the right type but an inappropriate value…
- `ZeroDivisionError`：Raised when the second argument of a division or modulo operation is zero.

**traceback 模組**（https://docs.python.org/3.13/library/traceback.html ）：錯誤訊息開頭印的是 `Traceback (most recent call last):`，接著是堆疊回溯，最後是錯誤的種類和內容。

**What's New 3.10**：`NameError` 會提示長得像的名字（`Did you mean`）。**What's New 3.13**：終端機裡的錯誤訊息預設有顏色（可以用 `PYTHON_COLORS`、`NO_COLOR` 關掉）。

## 5. 第③圈：AI 交回的 trip.py（課程準備的示意）

影片裡的 20 行程式（三天兩夜的旅費）。AI 用了 `days`，可是程式裡只設了 `day_count`：

```python

# 1. 天數，和每天吃飯、門票的花費
day_count = 3
day1 = 1280
day2 = 960
day3 = 450
# 2. 交通和住宿
train = 1500
hotel = 3200
# 3. 總花費
total = day1 + day2 + day3 + train + hotel
print(f"總花費 {total} 元")
# 4. 四個人平分
people = 4
each = total // people
rest = total % people
print(f"每人 {each} 元，零頭 {rest} 元")
# 5. 每人每天大約多少
per_day = each // days
print(f"每人每天大約 {per_day} 元")
```

跑起來（`uv run lessons/1-7/trip.py`）：

```

每人 1847 元，零頭 2 元
Traceback (most recent call last):
  File "/Users/bear/code/ledger/lessons/1-7/trip.py", line 19, in <module>
    per_day = each // days
                      ^^^^
NameError: name 'days' is not defined. Did you mean: 'day1'?
```

照 `Did you mean` 改成 `day1` 也跑得起來，可是算的是「每人的錢 ÷ 第一天的花費」，意思不對；註解寫的是每人每天，要除以天數 `day_count`（第 3 行）。改好以後印出「每人每天大約 615 元」。
