## 1. Traceback 每一行的意思

起點檔 `money.py`（1-3 的轉換機 to_yuan，最下面再試一次國字的一百）跑起來的原文：

```
1200
Traceback (most recent call last):
  File "/Users/bear/code/ledger/lessons/1-22/money.py", line 9, in <module>
    print(to_yuan("一百"))
          ~~~~~~~^^^^^^^^
  File "/Users/bear/code/ledger/lessons/1-22/money.py", line 4, in to_yuan
    return int(text)
ValueError: invalid literal for int() with base 10: '一百'
```

- 第一行 `1200` 是 `print(to_yuan("1,200"))` 印的：出錯以前的照樣會跑。
- `Traceback (most recent call last):`：「最後發生的，寫在最下面」，所以從最下面往上讀。
- 最後一行 `ValueError: invalid literal for int() with base 10: '一百'`：錯誤的種類（ValueError）和原因（int 看不懂 '一百'，沒辦法變成十進位的整數）。官方教學 8.2：The last line of the error message indicates what happened。
- 往上一組 `File "…money.py", line 4, in to_yuan` 和 `return int(text)`：錯誤從 to_yuan 的第 4 行丟出來。終端機太窄時，`File …` 那一行會折成兩行，是同一行。
- 再往上一組 `line 9, in <module>` 和 `print(to_yuan("一百"))`：是誰呼叫了它（`<module>` 是檔案最外層）。下面那排 `~~~^^^` 只是標出這一行的哪一段，可以先不管。

## 4. 這一課的幾個細節

**else 為什麼不直接寫在 try 裡？** 官方教學 8.3：The use of the else clause is better than adding additional code to the try clause because it avoids accidentally catching an exception that wasn't raised by the code being protected by the try … except statement。try 裡只放「可能丟出你要接的那種錯」的那一行，其他的放 else。

```python
def to_yuan(text):
    return int(text)

text = "120"
try:
    amount = to_yuan(text)
except ValueError:
    print("看不懂：", text)
else:
    print("記下", amount, "元")   # 寫在 else：這一行出錯，不會被上面的 except 誤接
finally:
    print("這筆看完了")
```

印出（Python 3.13 實際跑）：

```
記下 120 元
這筆看完了
```

**except 一次接好幾種：** 用括號寫成一組。只寫你知道怎麼辦的那幾種。

```python
for text in ["120", "一百", None]:
    try:
        amount = int(text)
    except (ValueError, TypeError) as e:   # 好幾種寫成一組，用括號包起來
        print("看不懂：", type(e).__name__, e)
    else:
        print("記下", amount, "元")
```

印出（Python 3.13 實際跑）：

```
記下 120 元
看不懂： ValueError invalid literal for int() with base 10: '一百'
看不懂： TypeError int() argument must be a string, a bytes-like object or a real number, not 'NoneType'
```

**光禿禿的 except、Exception、KeyboardInterrupt：** `except:`（後面什麼都不寫）什麼錯都接，連 Control C 丟出的 KeyboardInterrupt 也接（PEP 8：bare except is equivalent to except BaseException）。`except Exception:` 不會接 Control C，但打錯字的 NameError 一樣會被接住、藏起來。所以這門課的做法是：寫明你知道怎麼辦的那一種（像 `except ValueError`）。

```python
print(issubclass(ValueError, Exception))
print(issubclass(KeyboardInterrupt, Exception))       # Control C 丟出的那一種不是 Exception
print(issubclass(KeyboardInterrupt, BaseException))

def bare():
    try:
        raise KeyboardInterrupt   # 假裝按了 Control C
    except:
        return "光禿禿的 except 接住了"

print(bare())
```

印出（Python 3.13 實際跑）：

```
True
False
True
光禿禿的 except 接住了
```

**程式停不下來怎麼辦：** 按 Control C（Mac 和 Windows 都一樣）。被光禿禿的 except 接住、停不下來的話（像 `ai_bare.py`），打一個它接受的金額（例如 120）讓迴圈結束，或直接關掉終端機分頁再開一個。

**finally 常拿來做什麼：** 不管有沒有出錯都要做的收尾，像關掉打開的檔案。1-23 讀寫檔案會用 `with open(…)`，它會自己收尾。

### Built-in Exceptions：ValueError、KeyboardInterrupt（https://docs.python.org/3.13/library/exceptions.html）

```
exception BaseException¶
The base class for all built-in exceptions.  It is not meant to be directly
inherited by user-defined classes (for that, use Exception).  If
str() is called on an instance of this class, the representation of
the argument(s) to the instance are returned, or the empty string when
there were no arguments.
exception Exception¶
All built-in, non-system-exiting exceptions are derived from this class.  All
user-defined exceptions should also be derived from this class.
exception KeyboardInterrupt¶
Raised when the user hits the interrupt key (normally Control-C or
Delete).  During execution, a check for interrupts is made
regularly. The exception inherits from BaseException so as to not be
accidentally caught by code that catches Exception and thus prevent
the interpreter from exiting.
Note
Catching a KeyboardInterrupt requires special consideration.
Because it can be raised at unpredictable points, it may, in some
circumstances, leave the running program in an inconsistent state. It is
generally best to allow KeyboardInterrupt to end the program as
quickly as possible or avoid raising it entirely. (See
Note on Signal Handlers and Exceptions.)
exception TypeError¶
Raised when an operation or function is applied to an object of inappropriate
type.  The associated value is a string giving details about the type mismatch.
This exception may be raised by user code to indicate that an attempted
operation on an object is not supported, and is not meant to be. If an object
is meant to support a given operation but has not yet provided an
implementation, NotImplementedError is the proper exception to raise.
Passing arguments of the wrong type (e.g. passing a list when an
int is expected) should result in a TypeError, but passing
```

### PEP 8：bare except（https://peps.python.org/pep-0008/#programming-recommendations）

```
When catching exceptions, mention specific exceptions whenever
possible instead of using a bare except: clause:
try:
    import platform_specific_module
except ImportError:
    platform_specific_module = None
A bare except: clause will catch SystemExit and
KeyboardInterrupt exceptions, making it harder to interrupt a
program with Control-C, and can disguise other problems.  If you
want to catch all exceptions that signal program errors, use
except Exception: (bare except is equivalent to except
BaseException:).
A good rule of thumb is to limit use of bare ‘except’ clauses to two
cases:
If the exception handler will be printing out or logging the
traceback; at least the user will be aware that an error has
occurred.
If the code needs to do some cleanup work, but then lets the
exception propagate upwards with raise.  try...finally
can be a better way to handle this case.
When catching operating system errors, prefer the explicit exception
hierarchy introduced in Python 3.3 over introspection of errno
values.
```
