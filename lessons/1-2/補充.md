# 1-2 補充：變數，給資料取名字

影片說明欄放不下的參考資料。作業的完整步驟在同一個資料夾的 [README.md](README.md)。

## 等號是「放進去」

- `money = 100`：把 100 放進 `money` 這個名字。之後寫 `money`，Python 就拿出裡面放的值。
- `money = money - 35`：**右邊先算**（拿出 money 裡的 100，減 35，得到 65），再把 65 放回 money，原本的 100 就被換掉了。
- Python 官方教學的說法：The equal sign (=) is used to assign a value to a variable.（等號用來把一個值指定給一個變數。）〈An Informal Introduction to Python〉3.1.1，docs.python.org/3/tutorial/introduction.html
- 這門課先用「放進去」的說法。到 1-16（可變與參照）會看到更精準的說法：名字比較像貼在值上面的名牌。到時候再換，現在用「放進去」算數字不會出錯。

## 追蹤表怎麼畫

一行程式一列，每個名字一欄，寫下「這一行跑完以後」每個名字裡放的是什麼；有印東西的那一行，另外記印出了什麼。這一行沒改到的名字，照抄上一列。

影片裡熊的錢包：

| 跑完第幾行 | 程式 | money | 印出來 |
|---|---|---|---|
| 1 | `money = 100` | 100 | |
| 2 | `print(money)` | 100 | 100 |
| 3 | `money = money - 35` | 65 | |
| 4 | `print(money)` | 65 | 65 |

果凍兔少寫等號的那一版（`money - 35`）：第 2 行有算出 65，可是沒有放進任何名字，money 一直是 100，最後印出 100。

## 名字的規定和這門課的習慣

Python 的規定（照著寫才跑得動）：

- 只能用字母、數字、底線 `_`；不能用數字開頭（`2day` 不行），中間不能有空格或減號（`food total`、`food-total` 都不行）。
- 大小寫不一樣就是不同的名字：`Total` 和 `total` 是兩個名字。影片裡果凍兔打錯大小寫，跑出 `NameError: name 'Total' is not defined. Did you mean: 'total'?`（Python 3.13 實測；最後一句是 Python 猜你想打的名字）。
- `if`、`for` 這種 Python 自己用的關鍵字，不能拿來當名字（之後的課會一個一個認識）。

這門課的習慣（不照著寫也跑得動，但這樣寫比較好讀）：

- 名字說出裡面放的是什麼：`total` 比 `t` 好懂。
- 英文小寫，兩個字以上用底線接：`food_total`。Python 官方的寫法指南 PEP 8 寫：Variable names follow the same convention as function names（函式名稱是 lowercase, with words separated by underscores as necessary to improve readability）。
- 不要用 Python 本來就有的名字，例如 `sum`、`print`、`input`、`list`、`max`、`min`（下面「sum 為什麼會當掉」）。

## 中文名字：Python 3 可以用，熊為什麼先不採用

- **可以用，AI 沒說錯。** Python 3.0 開始，名字可以用英文以外的字（PEP 3131〈Supporting Non-ASCII Identifiers〉，peps.python.org/pep-3131/）。Python 官方文件〈Lexical analysis〉2.3.4 的例子：ř_1, 蛇, or साँप are valid names（docs.python.org/3/reference/lexical_analysis.html）。影片裡 `早餐 = 45`、`print(早餐)` 在 Python 3.13 實際跑出 45。
- **當初為什麼加這個功能。** PEP 3131 的理由：很多寫 Python 的人不熟英文，用自己的語言取名字，同一種語言的人讀起來更清楚、更好維護（By using identifiers in their native language, code clarity and maintainability of the code among speakers of that language improves）。所以中文名字不是錯的。
- **官方自己的規定。** 同一份 PEP 3131 也寫：Python 標準函式庫的名字一律只用 ASCII（英文字母、數字、底線），能用英文字就用英文字（All identifiers in the Python standard library MUST use ASCII-only identifiers, and SHOULD use English words wherever feasible）。PEP 8 再補一句：給全世界用的開源專案，鼓勵也這樣做（Open source projects with a global audience are encouraged to adopt a similar policy）。
- **熊的理由（實際的考量）。** 一、打中文名字要切到中文輸入法，切回英文之前，括號、引號很容易打成全形的，程式就停住（影片裡 `print（早餐）` 跑出 `SyntaxError: invalid character '（' (U+FF08)`，Python 3.13 實測）。二、這門課的作業、檢查程式都用英文名字，這一課的目標也是練習取看得懂的英文名字。
- **什麼時候可以再想。** 寫給只看中文的人用、自己維護的小程式，用中文名字是合理的選擇。熊的決定是「先不採用」，不是「中文名字不行」。

影片裡熊的判讀紀錄全文，在 `answers/record_example.md`。

## sum 為什麼會當掉

第③圈有一個版本，把合計取名叫 `sum`：

```python
sum = sum([juice, dinner, mrt])
print("合計", sum, "元")
food = sum([juice, dinner])
```

- `sum` 是 Python 本來就有的加總功能，`sum([50, 130, 25])` 會把方括號裡的數字加起來（方括號 1-13 才教，現在看懂這一句就好）。Python 官方文件〈Built-in Functions〉：sum(iterable, /, start=0) Sums start and the items of an iterable from left to right and returns the total.
- 第一行右邊先算：用本來的加總功能算出 205。接著放進左邊的名字，左邊也叫 `sum`，所以 `sum` 這個名字從此放的是 205，本來的加總功能被蓋掉了。
- 第三行又想用 `sum(...)` 加總，可是 `sum` 現在是 205，一個數字不能拿來當功能用，程式就停在這一行：`TypeError: 'int' object is not callable`（Python 3.13 實測；int 是整數，1-3 會教）。
- 所以印完「合計」就當掉了。只寫前四行預期輸出的人抓不到它；照需求卡寫完六行，就抓得到。
- 改法：合計取名 `total`，不要跟 Python 本來就有的名字撞到。

## 名詞小抄

| 名詞 | 白話 |
|---|---|
| 變數 | 幫一個值取的名字，之後用名字就拿得到它 |
| `=` | 放進去：右邊算好的值，放進左邊的名字（不是「等於」） |
| 追蹤表 | 每跑一行，記下每個名字裡放的是什麼 |
| 判讀紀錄 | AI 說了什麼、你查了什麼、你的決定和理由，寫成一張 |
| NameError | 程式用到一個沒放過東西的名字（常常是打錯字或大小寫） |
