# 1-9　if／elif／else：預算燈號與 BMI

這課大約 45 分鐘。三圈比例 70／20／10。Windows 同學：指令在 Git Bash 照打，⌘ 換成 Ctrl（安裝見 0-W）。
要會的：`input()` 和 `int()`（1-6）、比較 `<`、`<=`、`>`、`>=`、`==` 和 assert（1-8）。

## 1. 題目

**第①圈：自己寫（關掉 AI）。**

A. 預算燈號（`budget_light.py`）：先輸入這個月花了多少、再輸入預算，印出一個燈號。

| 花費占預算 | 燈號 |
|---|---|
| 低於 80% | 綠燈 |
| 80% 到 100%（**剛好 80%、剛好 100% 都算黃燈**） | 黃燈 |
| 超過 100% | 紅燈 |

B. 追蹤題（`trace.txt`）：先不要跑，用眼睛追一段 if／elif／else，寫出 4 個數字各會印出什麼。

**第②圈：判讀 AI 的建議（`ai_review.txt`）。** 影片裡，熊把預算燈號貼給家教，請它審查。這裡是它真的回的 6 則建議（完整對話在 `補充.md`）。每一則判成「採用、不採用、要查證」，寫一句理由，再對答案。最後挑你覺得最難判斷的一則，填你的第一張「AI 建議判讀卡」（`judgment_card.md`，自評，不擋過關）。

**第③圈：用 assert 替 AI 寫的 `bmi_level()` 驗收（`checks_bmi.py`）。** 需求卡：

| 欄 | 內容 |
|---|---|
| 目標 | 寫一個 `bmi_level(bmi)`，交回成人 BMI 的分級 |
| 背景 | 照衛生福利部國民健康署〈成人健康體位標準〉（本課只用來練程式，不是健康建議） |
| 限制 | BMI 小於 18.5 →「體重過輕」；18.5 以上、小於 24 →「健康體重」；24 以上、小於 27 →「體重過重」；27 以上 →「肥胖」。**剛好 18.5 算健康體重、剛好 24 算體重過重、剛好 27 算肥胖** |
| 怎樣算做完 | 你寫的 assert（至少 6 條）在正確版上全部成立；三個壞版本，各被至少一條抓到 |

課程準備了一個正確版（`reference/`）和三個壞版本（`mutants/`），其中一個把「24 那個邊界」寫錯了。你**不用寫它**，也不用看懂它的程式，只要在 `checks_bmi.py` 裡**呼叫**它，把一定要成立的事寫成 assert：

```python
from bmi import bmi_level

assert bmi_level(16) == "體重過輕"
```

`uv run check.py 1-9` 會把你的 `checks_bmi.py` 拿去跑正確版和三個壞版本（每個版本各跑一次、互不影響），正確版上要全部成立，每個壞版本至少要有一條不成立。

## 2. 提示

- `if` 後面接一個條件和冒號 `:`，下一行往右縮四格，是條件成立時才做的事。`else:` 是「不然的話」。沒有縮排的那一行，不屬於 if，不管成不成立都會做。
- `elif` 是「不然的話，再看看這個」。if／elif 是**從上往下看，第一個成立的那一條才會做，後面的就不看了**。所以順序很重要：把範圍比較寬的條件寫在前面，後面的就永遠輪不到。
- `elif` 跟另外再寫一個 `if` 不一樣：兩個獨立的 `if` 會各看各的，兩條都成立就兩條都做；`elif` 只有在前面都不成立時才會看。
- 「18.5 以上」包含 18.5（`>=`），「小於 24」不包含 24（`<`）。剛好等於邊界的數字最容易寫錯，也最值得檢查。
- `ratio` 是小數：花 800、預算 1000 的時候，`ratio` 是 0.8，不是 80。比較的時候寫 `0.8`、`1`。
- 第②圈三種判法：採用＝說得對，現在就能照做；不採用＝說錯了，或用到還沒學的東西（先記下來，學到了再回來）；要查證＝可能是對的，可是要自己跑一次（或查資料）才知道。白海豹會問：這條你學過嗎？證據是什麼？
- 第③圈的文字要一模一樣：`"健康體重"` 不是 `"正常"`，也不能少字。不確定的話，先在帳本跑 `print(bmi_level(22))` 看看。

## 5. 怎麼測

`uv run check.py 1-9` 會先問你：「你覺得會過幾題？」先猜一個數字再按 Enter，它才開始檢查。一共 19 題：

- 第一圈：`budget_light.py` 4 題（check 自己餵四組：花 500、800、1000、1001，預算都是 1000）、`trace.txt` 4 題
- 第二圈：`ai_review.txt` 6 題（答案在 `answers/ai_review.json`；判讀卡是自評，量表和範例在 `answers/judgment_card_example.md`）
- 第三圈：至少寫 6 條 assert、在正確版上全部成立、抓到 3 個壞版本。寫滿 6 條以前，只告訴你抓到幾個，不告訴你溜過去的是哪一種

沒過的，它只先告訴你第一個沒過的，修好再跑一次（想一次看全部，最後加 `--all`）。不到 10 分鐘就全對，它會印出提醒：只是提醒，不扣分。`judgment_card.md` 是自評，check 不檢查。

選做（影片沒有講）：如果你想到某一條連正確版都會當掉（例如傳文字 `"23"` 進去），在那一行最後加 `# 已知會當掉`；覺得需求本身沒講清楚（例如 BMI 是 0 或負數要交回什麼），加 `# 需求有問題`。標了的不算在 6 條裡，check 會另外對答案；標了「已知會當掉」的那一行自己試跑一定會當掉，請放在檔案最後面。

### 常見錯誤

| 你看到 | 意思 | 怎麼辦 |
|---|---|---|
| `error: Failed to spawn: check.py` | 你不在課程資料夾裡（多半是剛剛在帳本試跑完忘了切回來） | 先打 `cd ~/code/plusform-course`，或用完整路徑 `uv run ~/code/plusform-course/check.py 1-9` |
| `IndentationError` | if、elif、else 下面那一行沒有往右縮，或縮的格數不一樣 | 下面那一行往右縮四格；`elif`、`else` 要跟 `if` 對齊 |
| `SyntaxError: expected ':'` | if、elif、else 那一行最後少了冒號 | 補上冒號 `:` |
| `你的程式要的輸入比這題給的多` | 程式裡的 `input()` 比題目多 | 只留起點檔原本的兩個 `input()` |
| `比較兩個東西一不一樣，要用兩個等號 ==` | assert 裡寫成一個等號 | `assert bmi_level(25) == "體重過重"` |
| `ModuleNotFoundError: No module named 'bmi'` | 自己試跑時，`bmi.py` 不在同一個資料夾 | 在課程資料夾打 `uv run check.py start 1-9`，它會把 `bmi.py` 複製過去 |
