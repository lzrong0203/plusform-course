## 1. 影片裡熊跟家教的對話（逐字）

示範帳號、0-8 建好的家教專案「PyPy 熊的程式家教」，2026-11-15 在 Claude 網頁版（模型 Sonnet 5.5）實際錄的。AI 的回答沒有改過；同樣的問題，每次問的回答都會不一樣。

熊在 AI 寫的記帳程式裡看到一行，預算是 0、右邊明明會除以 0，卻沒有當掉。他問家教為什麼，請它先用一兩段話解釋，驗證的例子先不要給，他想自己想。

**熊（使用者）：**

```
我在 AI 寫的記帳程式裡看到這三行：
spent = 500
budget = 0
print(budget > 0 and spent / budget > 0.8)
我學過除以 0 會出現 ZeroDivisionError，可是這一行印出 False，沒有當掉。為什麼右邊的除以 0 沒有當掉？
我目前只學過 True、False 和 and、or、not。請先用一兩段話解釋，驗證用的例子先不要給我，我想自己想例子，驗證你說得對不對。
```

**家教（Claude）：**

```
這個問題你觀察得很仔細！先回到你的規則 1：你有自己試過把 budget 改成別的值，或是拿掉 budget > 0 and 再跑一次嗎？不過這題你已經明確要我先解釋，所以我先給你概念。

Python 在算 A and B 的時候，是由左往右、能少算就少算。and 的意思是「兩邊都要是 True，結果才是 True」，所以只要左邊 A 已經是 False，不管右邊 B 是什麼，整個結果都不可能是 True 了。這時 Python 就直接把結果定為 False，根本不會去算右邊的 B。這種行為叫做「短路求值」（short-circuit evaluation）。

套到你的三行：budget 是 0，所以左邊 budget > 0 是 False，Python 到這裡就停了，右邊的 spent / budget 從頭到尾沒有被執行，自然不會出現 ZeroDivisionError。這也解釋了 AI 為什麼要把 budget > 0 寫在左邊：它是在「先檢查除數不是 0，再放心去除」。

接下來換你了：想一想，你可以設計哪些例子來驗證我說的？提示一個方向：如果短路是真的，那把 budget > 0 和 spent / budget > 0.8 左右對調，結果會怎樣？你預測一下，再自己跑跑看，告訴我你的預測和實際看到的結果。
```

家教一開始先提醒協定的第一條（先說你試過什麼）；熊在問題裡已經明確要它先解釋，所以它先給概念。影片裡熊照它說的「短路」自己想了兩行（用 `1 / 0` 當偵測器：右邊真的算了就會當掉），又照它提示的方向把左右對調，三個結果都跟它說的一樣：

```
print(False and 1 / 0)      → False（左邊已經是 False，右邊沒有算）
print(True and 1 / 0)       → ZeroDivisionError: division by zero（左邊是 True，還要看右邊，一算就當掉）
spent = 500
budget = 0
print(spent / budget > 0.8 and budget > 0)   → ZeroDivisionError（左邊先除以 0，還沒輪到 budget > 0）
```

### Language Reference 6.11 Boolean operations

https://docs.python.org/3.13/reference/expressions.html#boolean-operations

```
6.11. Boolean operations¶
or_test  ::= and_test | or_test "or" and_test
and_test ::= not_test | and_test "and" not_test
not_test ::= comparison | "not" not_test
In the context of Boolean operations, and also when expressions are used by
control flow statements, the following values are interpreted as false:
False, None, numeric zero of all types, and empty strings and containers
(including strings, tuples, lists, dictionaries, sets and frozensets).  All
other values are interpreted as true.  User-defined objects can customize their

The operator not yields True if its argument is false, False
otherwise.
The expression x and y first evaluates x; if x is false, its value is
returned; otherwise, y is evaluated and the resulting value is returned.
The expression x or y first evaluates x; if x is true, its value is
returned; otherwise, y is evaluated and the resulting value is returned.
Note that neither and nor or restrict the value and type

argument.  This is sometimes useful, e.g., if s is a string that should be

### 官方教學 5.7 深入了解條件（繁中版）

```
5.7. 深入了解條件 (Condition)¶
使用在 while 和 if 陳述式的條件句可以包含任何運算子，而不是只有比較運算子 (comparisons) 。
比較運算子 in 和 not in 用於隸屬資格檢測，在容器中檢查一個值是否存在（或不存在）。運算子 is 和 is not 比較兩個物件是否真的是相同的物件。所有比較運算子的優先度都相同且都低於數值運算子。
比較運算是可以串連在一起的。例如， a < b == c 就是在測試 a 是否小於 b 和 b 是否等於 c。
比較運算可以結合布林運算子 and 和 or，且一個比較運算的結果（或任何其他布林運算式）可以加上 not 來否定。這些運算子的優先度都比比較運算子還低，其中，not 的優先度最高，or 的優先度最低，因此 A and not B or C 等同於 (A and (not B)) or C。一如往常，括號可以用來表示任何想要的組合。
布林運算子 and 和 or 也被稱為短路 (short-circuit) 運算子：會將其引數從左至右進行運算，當結果出現時即結束運算。例如，若 A 和 C 為真但 B 為假，則 A and B and C 的運算並不會執行到 C。當運算結果被當成一般值而非布林值時，短路運算子的回傳值為最後被求值的引數。
將一個比較運算或其他布林運算式的結果指派給一個變數是可以的。例如：
>>> string1, string2, string3 = '', 'Trondheim', 'Hammer Dance'
>>> non_null = string1 or string2 or string3
>>> non_null
'Trondheim'

## 3. `and`、`or` 交回的，其實是其中一邊的值

影片裡的真值表都用 `True`、`False`，所以印出來一定是 `True` 或 `False`。官方文件（上面 6.11）說得更精確：`x or y` 先算 `x`，`x` 算真就交回 `x`，不然交回 `y`；`x and y` 先算 `x`，`x` 算假就交回 `x`，不然交回 `y`。兩邊不是 `True`、`False` 的時候，交回來的就不是布林值（Python 3.13 實際跑）：

```
>>> 0 or 5
5
>>> "" or "未填"
'未填'
>>> 3 and 0
0
```

影片裡 `day == "六" or "日"` 印出「日」，就是這個原因：左邊不成立，`or` 交回右邊的 `"日"`；`"日"` 是有字的字串，當成真。所以 `or` 的兩邊要各寫一個完整的比較。`not` 不一樣：它一定交回 `True` 或 `False`。

AI 寫的程式常看到 `name = input("名字：") or "未填"`（什麼都沒打就用「未填」），用的就是這個規則。現在看得懂就好，這門課的作業不會要你這樣寫。

## 4. assert 的另一種寫法

影片和作業為了讓你看清楚「左邊算出來要等於什麼」，寫成：

```python
assert over_budget(1200, 1000) == True
assert over_budget(800, 1000) == False
```

Python 的風格指南 PEP 8 建議不要拿布林值跟 `True`、`False` 用 `==` 比（https://peps.python.org/pep-0008/ ，Programming Recommendations：Don’t compare boolean values to True or False using ==），比較常見的寫法是：

```python
assert over_budget(1200, 1000)
assert not over_budget(800, 1000)
```

兩種寫法 check 都收。別人寫的測試裡，比較常看到短的那一種，看到知道意思一樣就好。

## 5. `python -O` 會略過 assert

官方文件寫，用 `-O` 跑的時候「Remove assert statements」（上面第 2 節）。沙盒實測：同一支 `try_assert.py`（第 4 行那條不會成立），`python3.13 try_assert.py` 跳出 AssertionError；`python3.13 -O try_assert.py` 什麼都沒印、正常結束。

所以 assert 是拿來「檢查自己寫的程式對不對」的（這一課的驗收、之後的測試），不是拿來擋使用者打錯的字：要擋輸入錯誤，等 1-9 學了 if、1-22 學了錯誤處理再寫。這門課的 check 不會用 `-O` 跑你的檔。

## 6. check 1-08 怎麼判第③圈

- 你的 `checks_budget.py` 會被拿去跑 4 次：正確版一次、三個壞版本各一次。每次都是另外開一個 Python 程序，最多跑 10 秒，跑太久（例如寫出停不下來的迴圈）會被停下來；你的檔印出來的字不會混進結果。
- 只算最外層（最左邊不空格）的 `assert`；寫在 `if` 裡面的不算。
- 至少 5 條；正確版上要全部成立；每個壞版本至少要有一條不成立，才算「抓到」。寫滿 5 條以前，只告訴你抓到幾個，不告訴你溜過去的是哪一種。
- 常見的白話提示：寫成一個等號（`= False`）會說「要用兩個等號 ==」；寫成小寫 `true`、`false` 會說「第一個字母要大寫」；寫成 `"True"`（加了引號）會說「True、False 不加引號」。
