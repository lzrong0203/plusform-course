## 2. Python 官方文件原文

出處：Python 3.13 官方文件（2026-11-15 取得）。

**教學 5.5 Dictionaries**（https://docs.python.org/3.13/tutorial/datastructures.html#dictionaries）：

```
Another useful data type built into Python is the dictionary (see
Mapping Types — dict). Dictionaries are sometimes found in other languages as
“associative memories” or “associative arrays”. Unlike sequences, which are
indexed by a range of numbers, dictionaries are indexed by keys, which can be
any immutable type; strings and numbers can always be keys. Tuples can be used
as keys if they contain only strings, numbers, or tuples; if a tuple contains
any mutable object either directly or indirectly, it cannot be used as a key.
You can’t use lists as keys, since lists can be modified in place using index
assignments, slice assignments, or methods like append() and
extend().

It is best to think of a dictionary as a set of key: value pairs,
with the requirement that the keys are unique (within one dictionary). A pair of
braces creates an empty dictionary: {}. Placing a comma-separated list of
key:value pairs within the braces adds initial key:value pairs to the
dictionary; this is also the way dictionaries are written on output.

The main operations on a dictionary are storing a value with some key and
extracting the value given the key. It is also possible to delete a key:value
pair with del. If you store using a key that is already in use, the old
value associated with that key is forgotten.

Extracting a value for a non-existent key by subscripting (d[key]) raises a
KeyError. To avoid getting this error when trying to access a possibly
non-existent key, use the get() method instead, which returns
None (or a specified default value) if the key is not in the dictionary.

Performing list(d) on a dictionary returns a list of all the keys
used in the dictionary, in insertion order (if you want it sorted, just use
sorted(d) instead). To check whether a single key is in the
dictionary, use the in keyword.
```

**標準型別 dict：順序**（https://docs.python.org/3.13/library/stdtypes.html#mapping-types-dict）：

```
Dictionaries preserve insertion order. Note that updating a key does not
affect the order. Keys added after deletion are inserted at the end.

>>> d = {"one": 1, "two": 2, "three": 3, "four": 4}
>>> d
{'one': 1, 'two': 2, 'three': 3, 'four': 4}
>>> list(d)

>>> d
{'one': 42, 'two': 2, 'three': 3, 'four': 4}

Changed in version 3.7: Dictionary order is guaranteed to be insertion order. This behavior was
```

```
Return the value for key if key is in the dictionary, else default.
```

```
round(number, ndigits=None)¶

Return number rounded to ndigits precision after the decimal
point. If ndigits is omitted or is None, it returns the
nearest integer to its input.

For the built-in types supporting round(), values are rounded to the
closest multiple of 10 to the power minus ndigits; if two multiples are
equally close, rounding is done toward the even choice (so, for example,
both round(0.5) and round(-0.5) are 0, and round(1.5) is
2). Any integer value is valid for ndigits (positive, zero, or
negative). The return value is an integer if ndigits is omitted or
None.
Otherwise, the return value has the same type as number.

For a general Python object number, round delegates to
```

## 3. dict 的細節（Python 3.13 實際跑）

用方括號查一個沒有的鍵，會出現 KeyError；get 查不到交回第二個值（沒寫就是 None），而且 get 只是查，不會把鍵放進去：

```
>>> totals["醫療"]
KeyError: '醫療'

>>> totals.get("醫療", 0)
0

>>> print(totals.get("醫療"))
None

>>> print(totals)   # get 不會把鍵放進去
{'餐飲': 205, '交通': 80, '娛樂': 200}
```

dict 記得放進去的順序（Python 3.7 起是語言的保證）；換掉某個鍵的值，位置不變。1-14 的 set 沒有這個保證：

```
>>> d = {}
... d["交通"] = 1
... d["餐飲"] = 2
... d["娛樂"] = 3
... print(list(d))
... d["交通"] = 9
... print(list(d))
['交通', '餐飲', '娛樂']
['交通', '餐飲', '娛樂']
```

for 直接拿 dict 跑，拿到的是鍵；鍵和值一起要用 items()，全部的值用 values()：

```
>>> for k in {"餐飲": 205, "交通": 75}:
...     print(k)
餐飲
交通

>>> sum({"餐飲": 205, "交通": 75}.values())
280

>>> sum({"餐飲": 205, "交通": 75})
TypeError: unsupported operand type(s) for +: 'int' and 'str'
```

**小心**：寫成 `for kind, amount in totals:`（少了 .items()），拿到的是鍵，Python 會想把鍵拆成兩個名字。兩個字的鍵剛好拆得開，不會出現錯誤訊息，結果卻是錯的；三個字的鍵就拆不完：

```
>>> for kind, amount in {"餐飲": 205, "交通": 75}:
...     print(kind, amount)
餐 飲
交 通

>>> for kind, amount in {"日用品": 30}:
...     print(kind, amount)
ValueError: too many values to unpack (expected 2)
```

計數：一開始是空的 dict（空的大括號 {} 是 dict，1-14 的空 set 要寫 set()），第一次遇到的鍵 get 交回 0：

```
>>> counts = {}
... for kind in ["餐飲", "交通", "餐飲"]:
...     counts[kind] = counts.get(kind, 0) + 1
... print(counts)
{'餐飲': 2, '交通': 1}

>>> print(type({}), type(set()))
<class 'dict'> <class 'set'>
```

list 裡放 dict：先用索引拿第幾筆，再用鍵拿那一樣。同一個鍵在大括號裡寫兩次，後面的蓋掉前面的。兩個 dict 用 == 比，每一組鍵和值都一樣就相等，順序不用一樣：

```
>>> entries = [{"item": "午餐", "kind": "餐飲", "amount": 120},
...            {"item": "公車", "kind": "交通", "amount": 30}]
... print(entries[0]["amount"])
... print(entries[1]["item"])
... print(len(entries))
120
公車
2

>>> print({"餐飲": 1, "餐飲": 2})
{'餐飲': 2}

>>> print({"餐飲": 1, "交通": 2} == {"交通": 2, "餐飲": 1})
True
```

## 4. round 剛好一半時怎麼算

round 不是課本上的「四捨五入」。官方文件寫：兩邊一樣近的時候，選偶數那一邊（四捨六入五成雙）；另外小數在電腦裡大多存不準，看起來剛好一半的數，其實可能差一點點：

```
>>> print(round(0.5), round(1.5), round(2.5), round(3.5))
0 2 2 4

>>> print(round(0.125, 2), round(0.375, 2))
0.12 0.38

>>> print(round(2.675, 2))
2.67
```

0.125 和 0.375 在電腦裡存得剛好，所以照「選偶數」：0.12、0.38；2.675 存起來比 2.675 小一點點，所以是 2.67（官方說這不是 bug）。影片第③圈的 99.9 跟「剛好一半」無關（見下一節），所以影片只說「留到小數一位」。

## 5. 加總為什麼是 99.9

三類都是除不盡的：

```
>>> t = {"餐飲": 160, "交通": 100, "娛樂": 40}
... whole = sum(t.values())
... r = {k: round(v / whole * 100, 1) for k, v in t.items()}
... print(r)
... print(sum(r.values()), round(sum(r.values()), 1))
... print(160 / 300 * 100, 100 / 300 * 100, 40 / 300 * 100)
{'餐飲': 53.3, '交通': 33.3, '娛樂': 13.3}
99.89999999999999 99.9
53.333333333333336 33.33333333333333 13.333333333333334
```

每一類各自 round 到小數一位，都少了一點點（53.333… → 53.3、33.333… → 33.3、13.333… → 13.3），三個加起來少了 0.1。小數相加本身也有一點點誤差（1-3 的 0.1 + 0.2），所以比加總要先 round：

```
>>> print(33.3 + 33.3 + 33.3)
99.89999999999999

>>> print(33.4 + 33.3 + 33.3, round(33.4 + 33.3 + 33.3, 1))
99.99999999999999 100.0
```

程式照需求做了，round 也照它的規則做了：是需求同時要「每一類各自留到小數一位」和「加總顯示 100%」，又沒說少掉的這一點要給誰。這種時候不是自己猜一個答案改程式，而是回頭問出需求的人，把規則補上。影片裡熊補的是「誤差歸到最大的一類」，照這條規則算：

```python
t = {"餐飲": 160, "交通": 100, "娛樂": 40}
whole = sum(t.values())
r = {}
for kind, amount in t.items():
    r[kind] = round(amount / whole * 100, 1)
print(r, round(sum(r.values()), 1))
# 補上的規則：誤差歸到最大的一類
big = "餐飲"   # 這一組最大的是餐飲（def、max 的 key 寫法 1-18、1-20 才教，這裡先直接寫）
r[big] = round(r[big] + (100 - sum(r.values())), 1)
print(r, round(sum(r.values()), 1))
```

```
{'餐飲': 53.3, '交通': 33.3, '娛樂': 13.3} 99.9
{'餐飲': 53.4, '交通': 33.3, '娛樂': 13.3} 100.0
```

其他常見的規則也可以（例如歸到最後一類、照每一類被捨掉的大小分配），重點是寫進需求卡、大家照同一條做。作業 req_fix.txt 第 2 題 check 認的是「歸到最大的一類」這一條。

## 6. 燈號對照表為什麼寫 799

1-9 的規則：預算 1000 元，低於 80%（800 元）綠燈，80% 到 100%（剛好 800、剛好 1000 都算）黃燈，超過紅燈。dict 對照表每一燈存「最多花到幾元」，用 `spent <= top` 從頭比；
金額都是整數元（1-3），所以「低於 800」就是「最多 799」，「最多 1000」包含剛好 1000。

```python
spent = int(input("這個月花了多少？"))
limits = {"綠燈": 799, "黃燈": 1000}

light = "紅燈"
for name, top in limits.items():
    if spent <= top:
        light = name
        break
print(light)
```

for 照 dict 放進去的順序比，所以門檻要從小排到大（1-9 果凍兔把順序寫反、永遠綠燈，是同一個道理）。要多一種燈（例如最多 1200 元是橘燈），只要在 limits 裡多放一組，程式不用改；作業的 check 會在 limits 裡多加一燈再跑。
預算換了，這兩個數字要跟著改；學了函式（1-18）以後，可以照預算算出來。

## 7. 第③圈：三個壞版本錯在哪

課程的正確版（照需求卡第 1～3 條做；第 4 條「加總要顯示 100%」是需求沒定規則，不是程式的錯）：

```python
def shares(totals):
    whole = sum(totals.values())
    result = {}
    for kind, amount in totals.items():
        result[kind] = round(amount / whole * 100, 1)
    return result
```

**壞版本 1**：把占比直接寫回原本的 totals：交回的答案對，可是原本的小計被改掉了。check 沒抓到時的提示：「呼叫以後，原本的 totals 還是原本的小計嗎？」

```python
def shares(totals):
    whole = sum(totals.values())
    for kind, amount in totals.items():
        totals[kind] = round(amount / whole * 100, 1)
    return totals
```

**壞版本 2**：round 到整數：53.3 變成 53。check 沒抓到時的提示：「有小數的占比（像 53.3），交回來的留到小數一位了嗎？」

```python
def shares(totals):
    whole = sum(totals.values())
    result = {}
    for kind, amount in totals.items():
        result[kind] = round(amount / whole * 100)
    return result
```

**壞版本 3**：花 0 元的分類不見了（只放金額大於 0 的）。check 沒抓到時的提示：「花 0 元的分類，還在交回的 dict 裡嗎？」

```python
def shares(totals):
    whole = sum(totals.values())
    result = {}
    for kind, amount in totals.items():
        if amount > 0:
            result[kind] = round(amount / whole * 100, 1)
    return result
```

- 壞版本 1 交回的答案對，只看交回的抓不到：要在呼叫以後，再比一次原本的 dict（`assert t == {...}`）。1-13 也練過「交回的答案對，還要檢查有沒有動到原本的東西」；為什麼原本的會被改，1-16 會講。
- 壞版本 2：60.0 這種整數占比，round 到整數也是 60，`60 == 60.0` 成立，抓不到；要用有小數的例子（53.3）。
- 壞版本 3：要有一個花 0 元的分類。
- 全部都是 0 元的時候，正確版會除以 0、當掉（ZeroDivisionError）：可以標「# 已知會當掉」。
