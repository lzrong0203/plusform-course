## 4. 這一課的幾個細節

**import 只跑一次。** 官方教學 6.1：最外層的程式「只在第一次 import 的時候跑」。同一個程式 import 兩次，money.py 最上面的 print 也只印一次：

```
載入 money
1,820 元
```

**三種 import 寫法。** 影片用的是 `from money import fmt, total` 和 `import math`。AI 也常寫 `import datetime as dt`（as 是取一個比較短的別名）：

```
載入 money
1,250 元
1,250 元
1,250 元
```

**money.py 不在 main.py 旁邊**（例如 main.py 搬到別的資料夾、money.py 留在原地；import 會先找你跑的那個檔所在的資料夾，別的地方也沒有 money 時）：

```
ModuleNotFoundError: No module named 'money'
```

**格式碼大小寫意思不一樣。** 大寫 `%M` 是分鐘：照樣跑，月份卻變成預設的 1。字串和格式對不上時，才會出現錯誤訊息：

```python
from datetime import datetime

d = datetime.strptime("2026-11-03", "%Y-%M-%d")
print(d)              # 月份是 1、分鐘是 11：沒有錯誤訊息，結果卻錯了
print(d.month, d.minute)
ok = datetime.strptime("2026-11-03", "%Y-%m-%d")
print(ok.month, ok.day)
```

印出（Python 3.13 實際跑）：

```
2026-01-03 00:11:00
1 11
11 3
```

```python
from datetime import datetime

print(datetime.strptime("2026/11/03", "%Y-%m-%d"))   # 字串和格式對不上，才會出現錯誤訊息
```

印出（Python 3.13 實際跑）：

```
ValueError: time data '2026/11/03' does not match format '%Y-%m-%d'
```

**random 每次跑都不一樣。** 所以影片和作業只講「範圍」，不講某一次挑到什麼：

```python
from random import randint

r = [randint(1, 6) for k in range(1000)]
print(min(r), max(r))   # 每次跑挑到的不一樣，但一定在 1 到 6 之間（兩頭都包含）
```

印出（Python 3.13 實際跑）：

```
1 6
```

**Mac 和 Windows 的路徑寫法不同。** 用 `Path` 接，就不用自己決定用 `/` 還是 `\`：

```python
from pathlib import Path, PurePosixPath, PureWindowsPath

print(PurePosixPath("lessons") / "1-21" / "money.py")    # Mac、Linux 的寫法
print(PureWindowsPath("lessons") / "1-21" / "money.py")  # Windows 的寫法
p = Path("lessons") / "1-21" / "money.py"                # 用 Path：照你現在用的電腦自己選
print(p.name, p.suffix)
```

印出（Python 3.13 實際跑）：

```
lessons/1-21/money.py
lessons\1-21\money.py
money.py .py
```

**ModuleNotFoundError 的兩種原因。** 這台電腦沒裝，或根本不存在。標準函式庫一定 import 得到（不用裝）；import 不到的，再到 PyPI 搜尋看看。`uv run python -c "import 名字"` 只是試試看 import，不會替你安裝那個套件：

```python
import twmoney
```

印出（Python 3.13 實際跑）：

```
ModuleNotFoundError: No module named 'twmoney'
```

## 5. AI 編出來的套件名稱

Spracklen 等人的研究〈We Have a Package for You! A Comprehensive Analysis of Package Hallucinations by Code Generating LLMs〉（USENIX Security 2025，https://arxiv.org/abs/2406.10279 ）用 16 種寫程式的 AI、兩組題目，產生 576,000 段 Python 和 JavaScript 程式，檢查裡面的套件名稱。摘要的原話：「the average percentage of hallucinated packages is at least 5.2% for commercial models and 21.7% for open-source models」（商用模型平均至少 5.2%、開源模型 21.7% 的套件名稱是不存在的）。

PyPI 上的名字也不一定跟 import 的名字一樣。Python 官方的打包指南（https://packaging.python.org/en/latest/discussions/distribution-package-vs-import-package/ ）舉的例子是 Pillow：裝的時候叫 Pillow，import 的時候叫 PIL；它也寫明：「you cannot blindly install the PyPI package foo if you see import foo; this may install an unintended, and potentially even malicious package」（看到 import foo，不能直接去裝 PyPI 上叫 foo 的套件，可能裝到不是你要的、甚至是惡意的套件）。所以 PyPI 搜尋只是第一步：查不到可靠的出處，就先不要裝，請 AI 給官方來源。

論文也說明了危險在哪裡：有人可以把一個惡意的套件，用 AI 常編的那個名字放上套件網站，照著 AI 寫的去裝的人就會裝到它（第 1 節）。同一段也提醒：「the mere presence of a package in an open-source repository does not confirm its credibility」——查得到，也不代表一定安全。怎麼判斷一個查得到的套件能不能裝，4-8 會再講；這一課只做到：**查不到就不要裝，也不要找名字很像的來裝，退回去請 AI 改用標準函式庫或你自己的檔。**
