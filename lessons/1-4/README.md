**第②圈：判斷 AI 列的分帳情況。**

A. `ai_list.txt`（對答 4 題）：影片裡家教列的四種情況，每一條判斷 A 要寫進需求卡／B 熊的帳本不會發生／C 這一課先不做。

B. `my_list.md`（自評）：請 0-8 建好的家教專案列出**你**沒想到的分帳情況（只列情況、不要程式碼），一條一條判斷，至少挑一條用 Python 跑跑看它說的對不對。影片裡熊跟家教的完整對話在 `補充.md`。

**第③圈：替分帳機寫案例（`cases.txt`）。** 需求卡：

| 欄 | 內容 |
|---|---|
| 目標 | 一筆錢三個人分，算出每個人付多少 |
| 背景 | 吃飯要平分；退款也要分回去（退款記成負數） |
| 限制 | 每人相差不超過 1 元，加起來要等於原金額；零頭從第一個人開始，一人多付 1 元 |
| 怎樣算做完 | 你寫的案例，正確版都算得對；三個壞版本，各被你抓到 |

AI 照這張需求卡寫了分帳機 `split3`（課程凍結的版本：正確版在 `reference/`，三個壞版本在 `mutants/`）。你**不用看懂它的程式**，也先不要看，只寫案例表：每一行左邊是總金額（整數）、右邊是三個人各付多少（照順序、用逗號隔開）。至少 4 組，三個壞版本都要抓到。

```
1000 -> 334, 333, 333
```

## 2. 提示

- `/` 是一般的除，答案一定是小數（`1000 / 3` 是 `333.3333333333333`）。
- `//` 是除完只留整數，`%` 是除完剩多少（餘數）：`1000 // 3` 是 `333`、`1000 % 3` 是 `1`。驗算：`333 * 3 + 1` 剛好是 `1000`。
- `//` 是往**比較小的那邊**取整數，不是把小數點後面砍掉：`-7 // 2` 是 `-4`，不是 `-3`。`%` 跟著它走：`-7 % 2` 是 `1`，因為 `-4 * 2 + 1` 剛好是 `-7`。
- `**` 是次方：`2 ** 10` 是 `1024`。
- 先算哪一個：括號最先，接著次方，再來負號，然後乘、除、`//`、`%`，最後加、減。`-2 ** 2` 是 `-4`（先算 2 的平方再加負號）；要 -2 的平方，寫 `(-2) ** 2`。拿不準就加括號。
- 分帳的算法：每人先付 `總額 // 3`，零頭 `總額 % 3`（一定是 0、1 或 2），零頭從第一個人開始，一人多付 1 元。退款（負數）也照同一個算法，例如 `-7` 元：`-7 // 3` 是 `-3`、`-7 % 3` 是 `2`，三個人是 `-2, -2, -3`。
- `round()` 取最接近的整數，三個人都付 `round(1000 / 3)` 就是 333、少收 1 元。另外它遇到剛好一半時取偶數：`round(2.5)` 是 `2`（細節在 `補充.md`）。

## 5. 怎麼測

`uv run check.py 1-4` 會先問你：「你覺得會過幾題？」先猜一個數字再按 Enter，它才開始檢查。一共 17 題：

- 第一圈：`guess.txt` 7 題、`split.py` 印出三行（1 題）
- 第二圈：`ai_list.txt` 4 題
- 第三圈：`cases.txt` 至少 4 組、正確版都算得對、抓到 3 個壞版本

沒過的，它只先告訴你第一個沒過的，修好再跑一次（想一次看全部，最後加 `--all`）。不到 8 分鐘就全對，它會印出提醒：只是提醒，不扣分。`my_list.md` 是自評，check 不檢查。

check 全對就算這課過了，它會記在你帳本的 `.check/` 裡，不用上傳。在 VS Code 按一個存檔點（說明寫「1-4 完成」）。
