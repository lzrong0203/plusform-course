```
我在寫帳本的分帳：一筆錢三個人平分，金額都是整數元。
我的做法：每人先付 總額 // 3 元，零頭 總額 % 3 元給第一個人。
例如 1000 元：每人 333 元，零頭 1 元，三個人付 334、333、333。
請列出我可能沒想到的分帳情況，只要列情況，不要給程式碼。
```

**家教（Claude）：**

```
好的，你的做法（整除 + 零頭給第一個人）邏輯清楚。以下是你可能沒想到的情況，我只列情況，不給程式碼：

金額本身的邊界

總額剛好能被 3 整除（例如 900 元）：零頭是 0，三個人要付的金額會怎樣？
總額小於 3（例如 1 元、2 元）：每人先付的部分是多少？誰付錢、誰付 0？

總額是負數（例如退款、找零）：// 和 % 在負數時的結果，跟你直覺的「無條件捨去」一樣嗎？

零頭分配的公平性

零頭最多是 2 元（餘數只會是 0、1、2）：如果餘數是 2，第一個人一次付 2 元的零頭，還是兩個人各多付 1 元？哪種比較公平？
如果每次都是第一個人吃零頭，記很多筆帳之後，第一個人會不會長期多付？

資料與輸入

使用者輸入的是字串（例如 "1000"）或小數（例如 1000.5），而不是整數：你的做法還成立嗎？
輸入的是空值、文字、或負的小數：要怎麼處理？

結果的驗證

三個人付的金額加起來，是否永遠等於總額？你有沒有辦法檢查這件事？
如果之後要從三個人擴充成四個人、或 N 個人，你的做法哪些地方要改？

這些情況你可以挑幾個，用 Python 實際測試看看，再告訴我你看到了什麼結果。

如果你想從某一種情況開始，可以先說：你覺得哪一個最可能讓你的程式出錯？
```

## 2. Python 官方文件怎麼說（原文節錄，Python 3.13）

**`//` 往負無限大取整數**（[內建型別：數字運算](https://docs.python.org/3.13/library/stdtypes.html#numeric-types-int-float-complex)的註解 1）：

> Also referred to as integer division. For operands of type int, the result has type int. … The result is always rounded towards minus infinity: 1//2 is 0, (-1)//2 is -1, 1//(-2) is -1, and (-1)//(-2) is 0.

影片說的「往比較小的那一邊取整數」就是這一句：-3.5 往比較小的那邊是 -4，所以 `-7 // 2` 是 `-4`。不是把小數點後面砍掉（砍掉是 -3）。

**`//` 和 `%` 的關係**（[運算式 6.7](https://docs.python.org/3.13/reference/expressions.html#binary-arithmetic-operations)）：

> The modulo operator always yields a result with the same sign as its second operand (or zero) … The floor division and modulo operators are connected by the following identity: x == (x//y)*y + (x%y).

除以 3 的時候，`%` 的結果一定是 0、1 或 2（跟 3 同號），所以零頭最多 2 元；`(x//3)*3 + (x%3)` 一定等於 x，所以「每人先付的乘回去，加上零頭」一定等於原金額，退款（負數）也一樣。

**次方比左邊的負號先算**（[運算式 6.5](https://docs.python.org/3.13/reference/expressions.html#the-power-operator)；[教學 3.1.1](https://docs.python.org/3.13/tutorial/introduction.html#numbers) 的註腳）：

> The power operator binds more tightly than unary operators on its left; it binds less tightly than unary operators on its right.

> Since ** has higher precedence than -, -3**2 will be interpreted as -(3**2) and thus result in -9. To avoid this and get 9, you can use (-3)**2.

**先算哪一個**（[運算式 6.17 運算順序表](https://docs.python.org/3.13/reference/expressions.html#operator-precedence)，由先到後，只列這一課用到的）：括號 → `**` → 正負號 `+x`、`-x` → `*`、`/`、`//`、`%` → `+`、`-`。同一格的由左到右算（次方例外，由右到左：`2 ** 3 ** 2` 是 `2 ** 9`，512）。

**`round()` 取最接近的整數，剛好一半時取偶數**（[內建函式 round](https://docs.python.org/3.13/library/functions.html#round)）：

> If ndigits is omitted or is None, it returns the nearest integer to its input. … if two multiples are equally close, rounding is done toward the even choice (so, for example, both round(0.5) and round(-0.5) are 0, and round(1.5) is 2).

所以 `round(2.5)` 是 `2`、`round(3.5)` 是 `4`，跟學校教的四捨五入不一樣。分帳用 round 還有另一個問題：三個人都付 `round(1000 / 3)`＝333，加起來 999，零頭不見了。

## 4. 退款怎麼分（第③圈的提示）

需求卡說退款記成負數，也照同一個算法：每人先付 `總額 // 3`，零頭 `總額 % 3`（一定是 0、1 或 2），零頭從第一個人開始，一人多 1 元。拿 -7 元當例子：

- `-7 // 3` 是 `-3`（-2.33… 往比較小的那邊是 -3）
- `-7 % 3` 是 `2`（-3 × 3 + 2 = -7）
- 前兩個人各多 1 元：`-2, -2, -3`，加起來 -7。

退款 -1000 元那一組：影片第③圈熊把 bill.py 的總金額換成 -1000 跑過，每人先付 `-334`、零頭 `2` 元（-334 × 3 + 2 = -1000）。三個人各退多少，照上面的步驟（零頭從第一個人開始，一人多 1 元）自己算，寫進 cases.txt。check 只提示溜過去的是退款（負數）的金額；那個壞版本（課程準備的第 3 個）是先除、再把小數點後面砍掉（-333.3… 變成 -333），所以正數都對、退款會分錯。

## 5. 人數是 0 會怎樣

家教沒列到，但值得知道：除以 0 會跳出錯誤 `ZeroDivisionError: integer division or modulo by zero`（`1000 // 0`、`1000 % 0` 都會）。這一課的分帳機固定分給三個人，不會遇到；要讓人數可以改，就得先確定人數不是 0，1-9 學 if、1-22 學錯誤處理時會用到。
